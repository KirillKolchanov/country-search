# Country Search — DESIGN

## 1. Отмена устаревших запросов

Логика живёт в `createSearchController` (`src/app/search-controller.ts`) и не зависит от DOM.

- Контроллер хранит `AbortController` запроса, который сейчас в полёте (`activeRequest`).
- **На каждое изменение ввода** (`setQuery`) он сразу вызывает `activeRequest.abort()`, а не ждёт, пока debounce запустит новый запрос. Иначе за время ожидания debounce старый ответ успел бы прийти и отрисоваться под уже новым текстом.
- Каждый запрос получает новый `AbortController`. Его `signal` передаётся в `searchCountries` → `fetch`, поэтому браузер действительно обрывает HTTP-запрос (в Network он виден как `canceled`).
- Отменённый `fetch` отклоняется с `DOMException` `AbortError`. `classifySearchError` (`src/api/search-outcome.ts`) превращает его в исход `cancelled`, который контроллер просто пропускает — пользователь не видит ошибку.

**Таймаут.** `searchCountries` объединяет два источника отмены в один сигнал: `AbortSignal.any([signal, timeout.signal])`. У каждого источника свой `reason`: наша отмена даёт `AbortError`, таймаут — `TimeoutError`. Поэтому в `catch` они различаются: `AbortError` → `cancelled` (молча), `TimeoutError` → ошибка с кнопкой «Retry».

Таймаут сделан через `setTimeout` + `abort(new DOMException(..., 'TimeoutError'))` (функция `createTimeout`), а не через `AbortSignal.timeout`. В Node сигнал от `AbortSignal.timeout` внутри `AbortSignal.any` хранится по слабой ссылке и может быть собран GC до срабатывания — тест таймаута из-за этого зависал. Ручной вариант держит контроллер в таймере, а таймер очищается в `finally`, как только запрос завершён.

**Почему не флаг «актуальный ли ответ».** Флаг только прячет устаревший ответ, но запрос продолжает работать: тратит сеть, держит соединение и всё равно проходит парсинг. `abort()` останавливает сам запрос, освобождает ресурсы и делает отмену явной: её видно в Network и её можно проверить в тесте. В `src/app/race-condition.test.ts` мок `fetch` отклоняется с `AbortError` при `abort()`, и тест проверяет, что сигнал устаревшего запроса действительно отменён.

## 2. Задержка debounce — 300 мс

`SEARCH_DEBOUNCE_MS = 300` (`src/app/search-controller.ts`). Это примерно пауза между словами при обычном наборе: пока человек печатает, запросы не уходят, а после остановки результат появляется почти сразу.

- **Без debounce** запрос уходит на каждую букву: `s`, `sp`, `spa`, … Почти все они тут же отменяются, но всё равно нагружают сеть и сервер, а экран мигает индикатором загрузки.
- **Слишком большая задержка** (например, 1–2 с) — приложение кажется медленным: пользователь уже закончил печатать, а результата всё нет.

Индикатор загрузки показывается сразу при вводе, не дожидаясь debounce, — так старые результаты не висят под новым текстом.

## 3. Сложность

**`mapCountryResponse`** (`src/api/map-country-response.ts`) для одной страны — **O(L + C + B)**, где L, C, B — число языков, валют и границ: каждый из этих массивов один раз проходится `map` или копируется. Остальные поля переносятся за O(1). Для ответа из N стран — **O(N · (L + C + B))**, на практике линейно от размера ответа. Дополнительная память того же порядка: результат — новый объект с новыми массивами, вход не мутируется.

Кэш и дедупликация запросов (бонус) не реализованы.

## 4. Принципы чистого кода

- **Единственная ответственность.**
  - `searchCountries` — только HTTP: URL, `response.ok`, 404, таймаут;
  - `mapCountryResponse` — только преобразование данных;
  - `classifySearchError` — только разбор ошибок;
  - `createSearchController` — только состояние, debounce и отмена;
  - `src/ui/*` — только DOM.
- **Чистые функции.** `mapCountryResponse` и `classifySearchError` не имеют побочных эффектов и тестируются без сети.
- **Внедрение зависимостей.** `createSearchController` принимает функцию поиска параметром (`search`, по умолчанию `runSearch`), поэтому контроллер тестируется без `fetch`.
- **Явные типы вместо исключений в UI.** `runSearch` никогда не отклоняется и возвращает размеченное объединение `SearchOutcome` (`results` / `empty` / `cancelled` / `error`). `switch` по нему в `applyOutcome` и `renderState` TypeScript проверяет на полноту.
- **Свой класс ошибки.** `HttpError` (`src/api/http-error.ts`) хранит `status` — ошибки различаются по типу, а не по тексту сообщения.
- **Именованные константы вместо магических чисел.** `SEARCH_DEBOUNCE_MS`, `SEARCH_TIMEOUT_MS`, `NO_MATCHES_STATUS`.
- **Маленькие функции с говорящими именами.** `buildSearchUrl`, `createTimeout`, `formatCurrency`, `describeStatus`, `renderCountryCard`.
- **Безопасный DOM.** Хелпер `el()` (`src/ui/dom.ts`) пишет текст только через `textContent`; `innerHTML` запрещён правилом ESLint.
